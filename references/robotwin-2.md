# RoboTwin 2.0 — benchmark and data generator

- **Type**: peer-reviewed benchmark paper + official repository + dataset
- **Accessed**: 2026-11-25
- **Read scope**: arXiv abstract and **HTML body** (protocol and limitations
  sections); official project page and dataset listing via search results; the
  full PDF was not read end to end. Protocol/limitation claims below are A-grade
  for the paper's own statements; dataset-count claims from search results are B.

## Paper

- Chen, Chen, Chen, et al. *RoboTwin 2.0: A Scalable Data Generator and Benchmark
  with Strong Domain Randomization for Robust Bimanual Robotic Manipulation*.
  arXiv:2506.18088, submitted 2025-06-22; accepted at ICML 2026 per the project
  documentation. <https://arxiv.org/abs/2506.18088>
- 50 dual-arm tasks across five embodiments (Aloha-AgileX, ARX-X5, Franka, Piper,
  UR5); SAPIEN physics; RoboTwin-OD object library (731 instances / 147
  categories); >100,000 domain-randomized expert trajectories.
- Five structured domain-randomization axes: clutter, lighting, background,
  tabletop height, and language instructions. Table height varies up to 3 cm;
  random camera pose perturbation is capped at 1 cm.
- Evaluation protocol: "50 clean expert demonstrations per task are used for
  training"; "100 rollouts under two conditions: Easy (clean) and Hard"
  (randomized). `demo_clean` = easy, `demo_randomized` = hard.
- The paper reports a clean→randomized drop of 20.8 percentage points for RDT and
  30.1 for Pi0, i.e. the gap is benchmark-wide, not specific to SST.
- Stated limitation relevant to alternatives: "DP3's strong results partly stem
  from perfect point clouds and clean background segmentation in simulation."
  This is a caution for transferring DP3-style 3D policies to noisy real depth.

## Repository and dataset

- <https://github.com/RoboTwin-Platform/RoboTwin>
- Project page: <https://robotwin-platform.github.io/>
- Object/data: <https://huggingface.co/datasets/TianxingChen/RoboTwin2.0>;
  the LeRobot v3.0 unified dataset is `lerobot/robotwin_unified` (~79.6 GB,
  Apache-2.0) per the search summary.
- SST uses 2,500 episodes (50 tasks × 50 clean demos), 548,893 frames, and 100
  seen instructions per episode.

## Why this matters for the SST result

`demo_randomized` is generated by *strong* domain randomization across five axes.
A clean-only policy evaluated there is being tested on a synthetic appearance
shift that the benchmark deliberately makes large. This makes the benchmark a
good stress test but a weak predictor of real-camera robustness: the shift is
synthetic, the object set is closed (147 categories), and the instructions are
drawn from a fixed seen pool.

## Relevance to JCHENG

RoboTwin is a bimanual ALOHA-style benchmark; ArmPi Ultra is a 5-DoF single arm
with a gripper. The benchmark cannot be used as a target task set for JCHENG, and
success rates cannot be transferred. It is useful only as a controlled testbed
for the *mechanism* (appearance shift vs input conditioning).
